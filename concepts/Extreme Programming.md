# Extreme Programming (XP)

An [[concepts/Agile|agile]] methodology created by [[authors/Kent Beck|Kent Beck]]. Takes good practices to their logical extreme: if testing is good, test constantly (TDD); if integration is good, integrate continuously (CI); if design review is good, review constantly (pair programming).

## Core Practices
- [[concepts/Test-Driven Development]]
- Pair programming
- Continuous integration
- Small releases
- Simple design
- [[concepts/Refactoring]]
- Collective code ownership

## Relationship to Other Concepts
- Foundation of [[concepts/Agile]]
- TDD is XP's testing practice; [[concepts/Behavior-Driven Development|BDD]] evolved from it
- [[concepts/Refactoring]] is a first-class XP activity

- [[books/Extreme Programming Explained]] — the defining text (Beck)
- [[books/Planning Extreme Programming]] — planning practices (Beck & Fowler)
